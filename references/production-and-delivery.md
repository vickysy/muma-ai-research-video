# 制作与交付

## 最少记录
BRIEF 记对象、疑问、真实体验、主线、时长/语速、视觉、排除内容、交付范围。另存定稿、来源表、声画表（场景、旁白、素材、起止秒、结果）。工程、中间文件与发布文件分开。

复用工程不等于继承颜色、案例、页数。旧 build 脚本可能硬编码 Jev 和输出目录；复制前检查，不能覆盖已定稿文章/视频。

## 配音
使用当前使用者已授权且已配置的旁白音色。公开 Skill 不附带木妈个人音色或其使用授权。凭据从环境或现有安全配置读取，不进入 Skill、脚本、日志或压缩包。

默认原速配音后在声音层以 1.3 倍保调；若 TTS 已达目标速度，不重复加速。记录 source_duration、speed_factor、speed_applied_at、final_duration。改变旁白后重排画面和字幕，不只调播放器。
可用：ffmpeg -i narration-original.mp3 -af atempo=1.3 narration-1.3x.wav
保留原音频，先检查目标路径。

用真实分段/句级时间；仅有段落边界时，句内估时要如实标明，不能称字级对齐。重点检查专名与数字。局部改词只重做受影响语音和时间，避免重复付费。

## 真实媒体
- 创始人 B-roll 配观点概述，不伪装为逐字同步翻译。
- 保全动作与结果，结果页停留到能读懂。
- 短素材可停末帧或切已观察截图，不留长空白。
- 讲模型判断就突出该步骤，生成画面归给实际生成模型。
- 裁切放大关键区域，来源小字可读，复杂说明放资料文档。
- 不把多个剪辑点伪装成连续计时实测。

## HyperFrames（使用时才读相关 Skill）
读取入口与当前 CLI 文档，已有 BRIEF/工程直接续作，不重开访谈。按需用 core、media-use、audio、keyframes、cli。

Jev 工程的有效经验：
- host id、template id、timeline key 一致。
- 子合成媒体局部非零入点要明确时间基准，如 data-hf-media-start-basis="local"，按当前工具验证。
- 同场景后续片段的容器不能以不透明底色或提前显示的末帧挡住前段。
- 渲染前做布局/运行/代表帧检查，导出后再看实际 MP4 关键帧。
- 工具结果含 image_url/base64 时，只展示图像和输出路径，不打印整串二进制。
- 记录 CLI 版本；曾用 0.8.62 是历史信息，不要求以后锁死。

## 封面
采集当前官网/用户截图，记录配色与具体图形语言。3:4 和 4:3 分别排版，不硬裁。主钩子一个、观看收益一句，手机上可读。Jev 的粉黑点阵来自本次官网参考，其他产品重新选视觉。

用内置图像生成，生成后复制到项目；JPG 供上传，PNG 与提示词留底。检查精确宽高比，不只看文件名。只改封面时不重配音、不重渲染视频。

## 技术验收
Python 脚本只依赖标准库及 ffmpeg/ffprobe。在 Skill 所在目录执行（素材参数使用自己的文件路径）：
```bash
python3 scripts/verify_delivery.py \
 --video /absolute/video.mp4 --srt /absolute/video.srt \
 --portrait /absolute/cover-3x4.jpg --landscape /absolute/cover-4x3.jpg \
 --full-decode --report /absolute/verification.json
```

video 必填，其余按范围可选。--full-decode 才解码全片。编码不符默认值为 warning，损坏/缺音轨/字幕越界/比例错误为 error。脚本明确 visual_review 未完成，不能代替真实性检查、看图、实际语速及音色试听。

另查声画切口、每例结果、尾帧、中文，做音频响度/峰值检查；没做的检查保留待检查。用户已授权制作时通过验收就交付，不自增审批门槛。

## 交付
MP4 + 两封面 + 两平台纯文本发布文案；定稿、SRT、来源、工程及记录作附件。HTML 只是辅助，不能是唯一入口。用户只要 MP4 就先给 MP4。上传/草稿另需用户请求与回读，不以本地导出代替发布。
